# 下游输出契约梳理

当遗留脚本会写出文件、表、报表或其他产物，并且这些产物可能被其他任务或用户消费时，使用本技能。

## 输入

- 入口梳理阶段得到的输出路径。
- 对输出路径、文件名或字段名的仓库搜索结果。
- 已知下游报表、看板、批处理任务或用户。
- 可用的历史输出样例。

## 执行步骤

1. 通过搜索输出文件名、目录名、表名、报表名或字段名，识别直接消费者。
2. 记录输出契约：文件名模式、目录、字段结构、字段顺序、日期格式、数值精度、排序、编码、分隔符、空值表示、覆盖或追加行为。
3. 识别时序假设：每日运行时间、数据可用截止点、幂等性，以及下游是否会读取半成品文件。
4. 将消费者分类为关键、已知非关键、未知或废弃。
5. 在修改任何结构契约或格式前，为关键消费者定义兼容性测试。

## 输出格式

输出一张消费者契约表，包含：

- 消费者名称或路径。
- 消费的输出文件或表。
- 契约字段和格式假设。
- 破坏风险。
- 验证方法。
- 负责人或待确认负责人。

## 作为 subagent 任务时

本节点适合强委派给 subagent，因为下游依赖常分散在多个仓库目录、脚本、报表说明或字段引用中。

subagent 可以：

- 搜索输出路径、文件名、字段名和报表名。
- 梳理直接消费者和疑似消费者。
- 草拟输出契约表和兼容性测试建议。

subagent 禁止：

- 修改输出结构或下游代码。
- 将未知消费者判定为不存在。
- 批准任何破坏性契约变更。

必须交回：

- 消费者契约表。
- 关键消费者和未知消费者清单。
- 每个消费者的风险等级和验证建议。
- 需要主代理或用户确认的问题。

## 验收标准

- 关键消费者都有明确兼容性检查。
- 未知消费者被列为发布风险，而不是被忽略。
- 除非明确批准破坏性变更，否则新增能力应采用增量输出。
