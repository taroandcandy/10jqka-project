# 脏数据样例设计

当数据处理变更需要明确处理不完整、重复或混合领域 CSV 行的行为时，使用本技能。

## 输入

- 当前输入结构契约。
- 目标输出结构契约。
- 已知的缺失日期、重复行和空字段业务规则。
- 旧输出兼容性约束。

## 未明确规则时的默认处理

- 停牌导致的缺失交易日：除非用户明确选择前向填充，否则不要为单股票移动平均线合成收盘价；缺失日期应写入诊断信息。
- 重复的股票-日期行：默认视为错误或进入隔离区；如果必须给出确定性规则，则在稳定排序后保留最后一行，并记录警告。
- 必需价格字段为空：该行不参与移动平均线计算，并记录警告。
- 多股票输入：先按股票代码分组，再分别计算移动平均线。
- 跨行业输入：先计算单股票指标，再按行业聚合。
- 旧单股票输出：除非使用明确的新输出路径，否则保留旧字段和旧格式。

## 输出格式

输出一组紧凑测试样例，包含：

- CSV 输入行。
- 每一行覆盖的场景。
- 预期清洗决策。
- 预期移动平均线行为。
- 预期旧输出兼容行为。
- 预期新行业输出行为。

## 作为子代理任务时

本节点适合受控委派给子代理。子代理可以帮助扩展边界样例，但最终业务规则必须由主代理统一，避免不同样例之间出现互相矛盾的处理口径。

子代理可以：

- 草拟最小 CSV 输入样例。
- 覆盖停牌、重复行、空字段、多股票和跨行业场景。
- 给出每个样例的预期清洗和计算行为。

子代理禁止：

- 独自决定缺失交易日是否前向填充。
- 独自决定重复行保留策略。
- 修改旧输出兼容规则。

必须交回：

- 样例行和覆盖场景。
- 每个样例对应的预期行为。
- 需要主代理或用户确认的业务规则。
- 与旧输出兼容性相关的风险提示。

## 验收标准

- 每条脏数据规则至少有一行输入样例和一个预期结果。
- 预期输出必须是确定性的。
- 诊断信息要区分数据质量警告和致命错误。
