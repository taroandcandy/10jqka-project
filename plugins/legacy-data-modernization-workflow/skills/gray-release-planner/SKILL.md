# 灰度发布规划

当遗留数据处理变更准备进入受控交付时，使用本技能。

## 输入

- 新行为摘要。
- 兼容性审查结果。
- 测试结果。
- 消费者契约表。
- 已知运行调度和负责人。

## 执行步骤

1. 发布期间保持旧路径可用。
2. 先运行影子模式：执行新路径，但不喂给下游消费者。
3. 在安全时使用双写：保留旧输出，同时将新输出写到独立路径。
4. 先按小股票池、选定行业或非关键消费者灰度，再逐步扩大。
5. 对于应保持一致的行为，对比新旧输出。
6. 监控数据质量诊断、行数、空值数、重复数、运行耗时、失败率和下游报表成功率。
7. 在发布开始前定义回滚触发条件。

## 输出格式

输出一份发布计划，包含：

- 发布阶段。
- 每个阶段的范围。
- 功能开关或配置开关。
- 指标和阈值。
- 下游验证。
- 回滚触发条件。
- 回滚步骤。
- 沟通检查清单。

## 默认回滚触发条件

- 旧输出结构契约或基准差异出现非预期变化。
- 下游报表失败，或产生明显不同的行数。
- 缺失、空值、重复数据诊断超过约定阈值。
- 运行耗时超过批处理窗口。
- 新路径产出半成品文件或不一致文件。

## 验收标准

- 回滚尽可能不依赖重新部署代码，而是通过开关恢复旧路径。
- 每个阶段都有明确的继续、暂停或回滚判断。
- 灰度期间负责人和消费者知道哪个输出路径是权威路径。
