# 安全重构切片

当遗留脚本需要新增能力，但大范围重写会带来兼容性风险时，使用本技能。

## 输入

- 入口地图。
- 旧行为基线。
- 新需求。
- 兼容性契约。

## 执行步骤

1. 区分纯重构和行为变更。
2. 优先做无行为变化的抽取：把解析、计算和输出写入封装到函数后面，但不改变可观察输出。
3. 每次抽取后先补测试，再进入下一步变化。
4. 新行为通过功能开关或新命令选项引入。
5. 新结构契约和聚合结果优先采用新增输出，而不是直接替换旧输出。
6. 在灰度发布通过前保留旧入口路径，让回滚足够简单。

## 建议切片

- 抽取 CSV 读取器，不改变输出。
- 抽取移动平均线计算器，并通过基准文件一致性验证。
- 抽取输出写入器，精确保留旧结构契约。
- 在新选项后面增加多股票分组。
- 增加脏数据诊断，但不改变旧输出。
- 将行业聚合作为新输出文件增加。
- 增加兼容适配层和发布开关。

## 输出格式

输出一份有序实现计划，包含：

- 切片名称。
- 可能涉及的文件。
- 属于行为变更还是无行为变化重构。
- 所需测试。
- 回滚影响。
- 审查重点。

## 作为子代理任务时

本节点适合受控委派给子代理。子代理可以草拟切片候选，但最终切片顺序、变更边界和实施节奏必须由主代理结合真实代码和测试基线确认。

子代理可以：

- 根据需求、入口地图和旧行为基线提出切片计划。
- 标出每个切片是无行为变化重构还是行为变更。
- 建议每个切片需要的测试和审查重点。

子代理禁止：

- 把大范围重写作为默认方案。
- 合并结构重构和用户可见行为变更。
- 直接决定实现顺序或删除旧路径。

必须交回：

- 候选切片列表。
- 每个切片的风险、测试和回滚影响。
- 需要主代理确认的顺序依赖。
- 不建议采用的大范围重写点及原因。

## 验收标准

- 除非明确说明理由，不允许一个切片同时包含大结构调整和用户可见行为变化。
- 每个切片都有窄范围测试目标。
- 发布完成前旧路径仍然可调用。
