# 回归验证设计

当遗留数据脚本完成扩展或重构设计后，使用本技能设计验证体系。本节点专门对应工作流中的“验证”阶段。

## 输入

- 旧行为基线和基准输出。
- 功能扩展设计。
- 重构切片计划。
- 下游消费者契约表。
- 脏数据样例和预期行为。
- 兼容性风险清单。

## 执行步骤

1. 设计单元测试：覆盖解析、清洗、移动平均线计算、行业聚合和输出写入。
2. 设计基准文件回归测试：对旧单股票路径做精确输出对比。
3. 设计结构契约测试：检查字段名、字段顺序、日期格式、数值精度、编码、分隔符和空值表示。
4. 设计下游报表冒烟测试：确认旧输出仍能被报表或批处理任务读取。
5. 设计新旧结果差异对比：对于应保持一致的旧路径，要求差异为零；对于有意变化，要求差异可解释。
6. 设计脏数据诊断验证：检查停牌、重复行和空字段是否产生预期 warning 或隔离结果。
7. 设计批量性能验证：检查多股票输入下的运行时间、内存、文件数量和失败率。

## 输出格式

输出一张验证矩阵，包含：

- 测试类别。
- 覆盖风险。
- 输入样例。
- 预期结果。
- 失败时含义。
- 是否阻断发布。
- 对应的工作流门禁。

同时输出：

- 发布前必须通过的最小测试集合。
- 可灰度期间继续观察的指标。
- 无法自动化验证的人工检查项。

## 作为 subagent 任务时

本节点适合强委派给 subagent，因为验证矩阵容易展开，且产物可以独立审查。

subagent 可以：

- 根据需求和契约草拟测试矩阵。
- 补充边界用例和预期结果。
- 标记哪些失败应阻断发布。

subagent 禁止：

- 修改测试或生产代码。
- 把未运行的测试标记为已通过。
- 降低兼容性关键测试的阻断等级。

必须交回：

- 验证矩阵。
- 发布阻断测试清单。
- 灰度期观察指标。
- 自动化缺口和人工检查项。

## 验收标准

- 验证体系覆盖旧行为、新能力、脏数据、下游兼容和性能。
- 每类风险都有明确测试或监控手段。
- 失败含义和发布阻断条件清晰。
- 结果能直接进入兼容性审查和灰度发布规划。
