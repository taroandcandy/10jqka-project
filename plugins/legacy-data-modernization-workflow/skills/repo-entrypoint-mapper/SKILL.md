# 遗留仓库入口梳理

在遗留系统改造开始时使用本技能，用于理解脚本如何被调用，以及哪些代码路径是真正在运行的生产路径。

## 输入

- 仓库根目录或源码文件路径。
- 已知命令、cron 任务、CI 任务或调度器名称。
- 已知生产参数、配置文件或运行环境信息。

## 执行步骤

1. 盘点候选入口：带有 `if __name__ == "__main__"` 的 Python 脚本、控制台脚本、Shell 包装脚本、持续集成任务、定时任务配置、调度平台任务、笔记本和文档中的运行命令。
2. 追踪运行输入：命令行参数、环境变量、配置文件、硬编码路径、输入文件匹配规则和默认日期。
3. 从每个入口追踪调用路径，覆盖解析、清洗、计算、聚合和输出写入代码。
4. 将代码标记为生产活跃路径、测试路径、疑似废弃路径、未知路径或共享工具。梳理阶段不要删除看似废弃的代码。
5. 将已确认事实、推断假设和待确认问题分开记录。

## 输出格式

输出一份入口地图，包含：

- 入口路径和调用命令。
- 调用方或调度器。
- 必需输入和配置。
- 主要调用函数。
- 产出的输出文件。
- 需要人工确认的未知项。

## 验收标准

- 至少一个调用路径可以在本地复现；如果无法复现，必须记录阻塞原因。
- 每个计划中的行为变更都能追溯到一个活跃入口。
- 未确认的生产入口必须作为发布风险记录，不能静默忽略。
